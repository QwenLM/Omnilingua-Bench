# 子集与覆盖

## Omnilingua-LongASR · 音频

**任务**：给定长音频和文本任务指令，输出完整的原语言转写，考察持续识别、跨长上下文的完整性以及重复、截断、空输出等稳定性问题。

**支持语种**：10 种，`zh, en, es, fr, ja, ko, id, ru, ar, th`。对应 10 个 `L → L` 同语转写方向，不是跨语言翻译。支持范围与原始源清单的语言范围一致。

**指标设计**：以 WER 为主，同时报告空输出、重复、截断与有效评分率。正式发布需固定各语言文本归一化、分词／字符计数方式和异常输出规则；不同历史评分器的过滤策略不应直接混用。不要删除困难样本后只公布剩余样本的 WER。

## Omnilingua-MSpeaker · 多说话人

### 音频轨道（audio）

**任务**：同时输出转写文本、匿名说话人 ID、片段起止时间，仅利用声音。输出说话人 ID 不等于识别真实人物身份。

**支持语种**：6 种，`es, fr, ja, ko, ru, th`；对应源清单中的 **297 条记录**，均来自社交媒体公开视频。支持范围与当前源清单的语言范围一致。

**媒体引用方式**：数据集只提供视频 URL（`source_url`）与在原视频中的起止区间，**不包含、不复制、不再分发任何媒体文件**，需使用者自行下载。297 条样本来自 **105 个去重视频**，同一视频可被切为多个不同时间段的样本（最多 7 段），因此记录数不等于去重媒体数。

| 代码 | 语言 | 源记录数 |
| --- | --- | ---: |
| es | 西班牙语 | 50 |
| fr | 法语 | 47 |
| ja | 日语 | 50 |
| ko | 韩语 | 50 |
| ru | 俄语 | 50 |
| th | 泰语 | 50 |
| 合计 | 6 种 | 297 |

297 条清单均带起止区间：累计约 **26.27 小时**，单条 **25.00–1,706.07 秒**。这是输入区间之和，不代表去重媒体总时长，未逐文件解码验证。法语为 47 条而非 50 条，是因为维护者已按记录移除少量敏感片段；该删除针对特定时间段，不意味着对应视频整体不可用。

**已发布数据集**：`Omnilingua-MSpeaker/Omnilingua-MSpeaker_v202609_public.jsonl`（`split=test`、`subset_version=v202609`、**297 条**）。该数据集由 open benchmark 源清单经内部构建脚本转为统一格式（见 `released_manifest.built_from`），条数与语言分布与上表一致。`input.media[].source_url` 引用原始视频区间（`source_start_sec`／`source_end_sec`），仓库不含媒体文件；参考标注（转写、匿名说话人与时间戳）保存在 `reference.segments`。区间累计约 **26.27 小时**、单条 **25.00–1,706.07 秒**。数据许可证 **CC BY-NC 4.0**。

**指标设计**：tcpWER（带时间约束的说话人排列不变词错误率）、cpWER（说话人排列不变词错误率）和 DER（说话人分离错误率）。正式评分需固定时间容差、重叠语音处理、归一化方式和评分器版本。文本错误率与 DER 分别报告，不混为一个分数。

### 音视频轨道（audiovisual）

**任务定位**：在多说话人转写、说话人归属与时间对齐中联合使用音频和视频；作为 Omnilingua-MSpeaker 的独立评测轨道组织和报告，不与音频轨道混计。

**覆盖与状态**：音视频轨道与音频轨道共用同一批源音视频（同样的 297 个视频区间、同样的 6 种语言、相同的 `source_url` 与起止区间）——音频轨道只消费音频，音视频轨道额外使用视频画面；二者作为独立轨道分别报告、不混计。音视频输入无需另行发布：同一份已发布清单的 `source_url` 即为含画面的原始视频，按相同起止区间下载即可获得视频轨道，参考标注（`reference.segments`）与音频轨道共用。仍需在评测协议中明确视觉使用方式（帧采样、音画同步）与视频内字幕是否可见（防止转写答案泄漏）。

**拟定指标**：tcpWER、cpWER、DER；需补充视觉使用协议、帧采样参数和音画同步规则，明确视频字幕是否可见，防止转写答案泄漏。

## Omnilingua-MaXIFE · 音频／音频＋文本

**任务**：听取语音指令，结合可选文本上下文生成满足多项约束的回答。保留真实模态组合，不能将语音指令的完整转写额外提供给模型。

**支持语种**：7 种中高资源语言，`fr, id, ja, ko, it, pt, tr`，即法语、印尼语、日语、韩语、意大利语、葡萄牙语、土耳其语；对应源清单中的 **5,387 条记录**。

**已发布数据集**：`Omnilingua-MaXIFE/Omnilingua-MaXIFE_v202609_public.jsonl`（`split=test`、`subset_version=v202609`、**5,387 条**）。7 语种共 5,387 条（fr 755、id 773、it 766、ja 769、ko 781、pt 753、tr 790），样本 id 为 `maxife-<lang>-<n>`，`input.media[].path` 是相对子集根目录的真实路径（如 `fr/audio/fr_fr_5_c21f96.wav`），随仓库以 git LFS 附带 24 kHz mono WAV；`audio` 轨道 5,166 条、`audio_text` 轨道 221 条（后者在音频之外附文本上下文）。语音由商用云端 TTS 模型从文本 MaXIFE 单语子集合成、我方自有；该子集采用**双许可**：文本内容（指令、可朗读文本、约束）沿用上游 MaXIFE 的 **MIT** 许可证，合成语音（WAV）采用 **CC BY-NC 4.0** 许可证（两份许可证文本见该目录下 `LICENSE`），与本基准以 `source_url` 引用的第三方原始媒体性质不同。该子集是四者中唯一随仓库附带媒体的。清单由逐语种 parquet 经 `tools/build_maxife_manifest.py` 转换而来（parquet 已删除，SHA-256 见 `released_manifest.built_from`），逐文件校验值见 [subsets.json](../metadata/subsets.json) 的 `released_manifest`。

**原始全量源统计（非当前支持范围）**：9 种语言、6,886 条记录，下表中的英语 `en`（725 条）和中文 `zh`（774 条）未纳入当前支持范围。原始全量源清单中 **6,559 条只有音频输入块，327 条同时包含音频和文本输入块**；当前 7 语种范围的输入组合分布待重新统计。

**覆盖口径**：当前支持 7 种中高资源语言；原始源清单的 9 种语言标签不是当前支持语种数，也不意味着所有输出语言或跨语言方向均已核实。源语言、指令语言与要求的输出语言需在正式统一清单中分别标注。

**指标设计**：每条样本内先平均各约束分，再对样本平均，得到 `constraint_score`；所有约束均满足的样本比例为 `all_constraints_pass_rate`。历史实现允许部分约束有 0、0.7、1 等分值，因此平均约束分不等于二元“准确率”。还应分别报告约束类别、语言和失败率；需要模型裁判的约束必须固定裁判模型、模板、采样参数和超时策略。裁判故障不是模型的零分。

**数据许可证**：随仓库发布的 `Omnilingua-MaXIFE/` 采用双许可——文本内容（指令、可朗读文本、约束）沿用上游 MaXIFE 的 **MIT**，合成语音（WAV）为 **CC BY-NC 4.0**；该子集不含以 URL 引用的第三方原始媒体。

## 统一报告原则

1. 比较同一 `subset_version`、轨道和样本 ID 集合；数据集 SHA-256 不同就先核对差异。
2. WER/cpWER/tcpWER 的微平均按累计错误数除以累计参考长度计算；语言宏平均对各语言指标等权平均。
3. 同时报 `n_total`、`n_scored`、`n_failed` 与失败原因；基础设施失败不能静默当作零分或成功。
4. 音视频与音频结果分开；跨语言结果分开；不对异质指标直接平均。
5. 当前仓库没有评分实现或正式排行榜，上述内容是发布时应落实的协议设计。
